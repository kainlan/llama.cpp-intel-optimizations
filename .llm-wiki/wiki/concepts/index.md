# concepts

## Concepts

- [A/B harness (_TRACE/_COMPARE)](ab-harness-tracecompare.md) — Built-in env-var pairs (e.g., _TRACE=1, _COMPARE=1 + _COMPARE_LIMIT) that make a decision revisitable from one build via two env-var runs, without patching or a second libggml-sycl.so.
- [Accepted is not the same as correct](accepted-is-not-the-same-as-correct.md) — A primitive being accepted by oneDNN (no refusal in the log) does not guarantee correct numerics — the 3-D WOQ scale mask is accepted yet reproducibly wrong on B70; the same trap as ext_oneapi_enable_peer_access.
- [Accuracy ratio](accuracy-ratio.md) — Scoring kernel accuracy as the fit ratio between candidate oracles (dfloat must fit ≥100× better than q8_1-MMVQ) rather than as an absolute tolerance against one oracle.
- [Across-process spread](across-process-spread.md) — Basing figures on mean ± sd across ≥5 separate processes with min–max range, never llama-bench's tighter within-process ±.
- [allocation_control_class](allocationcontrolclass.md) — The stamp on each owner (CACHE_BACKING, CACHE_SUBALLOCATION, EXTERNAL_EXACT) that is the enforceable part of the contract, specified in the canonical doc §3.1.
- [Baseline measurement discipline](baseline-measurement-discipline.md) — Mean ± sd across ≥5 separate processes, free VRAM recorded each run, GT-reset checks before/after, and selector-based device keying.
- [Bench-guard preflight refusal](bench-guard-preflight-refusal.md) — The three ordered host-health preflight checks (stale GPU tenant, Shmem ceiling, PL2 throttle/active card) that can refuse a benchmark run with exit 3.
- [bench-guard VALID/SUSPECT verdict](bench-guard-validsuspect-verdict.md) — First-line stamp on every archived benchmark log; a number whose log does not start with '# bench-guard: VALID' is not a citable baseline.
- [Buffer-scoped weight provenance](buffer-scoped-weight-provenance.md) — A second legitimate owner-minting occasion at buffer allocation, seeded from managed_meta.id and namespaced by the top bit (1ull << 63), so buffer and model Registry id spaces are disjoint by enforcement.
- [Capability query vs capability check](capability-query-vs-capability-check.md) — can_access_peer is the honest device-level capability query, whereas enable_peer_access is a no-op on no-P2P hardware and not a valid capability check.
- [Correctness gates before throughput](correctness-gates-before-throughput.md) — Mistral/GPT-OSS completion gates that must pass before any llama-bench number is trusted, on both arms of any A/B.
- [Cross-device in-order dependency fixes](cross-device-in-order-dependency-fixes.md) — Local compute-runtime fixes for ordering dependencies across devices, carried in the patched 26.22 build — a historical build no longer loaded on this machine.
- [DEVICE_LOST on multi-GPU context](devicelost-on-multi-gpu-context.md) — Behavior where the single-context multi-GPU Level Zero configuration on compute-runtime 26.x triggers DEVICE_LOST, motivating per-device isolated contexts in the test.
- [Diverted library path / symlink rollback](diverted-library-path-symlink-rollback.md) — Installing the patched driver via a diverted libze_intel_gpu.so.1 symlink with stock/prior versions preserved, enabling rollback without removing the diversion.
- [DMMV coalesced fallback](dmmv-coalesced-fallback.md) — Coalesced dot-product kernel that is a fallback/debug path, not the production batch=1 TG kernel for reorder-eligible types.
- [Efficiency goal is 80% of hardware theoretical peak](efficiency-goal-80pct-hardware-theoretical-peak.md) — Owner ruling (llama.cpp-0oad, 2026-09-01) that the ≥80% efficiency target means 80% of the card's theoretical peak — memory-bandwidth utilization for decode, INT8 XMX compute utilization for prefill — never 80% of another model's measured tok/s.
- [Epoch-refcounted transient zones](epoch-refcounted-transient-zones.md) — A ring of equal-sized regions each carrying a live-handle counter (the epoch) that rewinds on zero, giving reset-only scratch/staging zones a real per-allocation release path without replacing the bump allocator or the reset.
- [Fail-closed admission contract](fail-closed-admission-contract.md) — Once an XMX_TILED-claimed op reaches the batched MoE PP executor, every internal decline throws ggml_sycl_fallback_error rather than returning false, because the outer dispatch has already skipped every other route that could decode the claimed layout.
- [Fail-closed contract](fail-closed-contract.md) — Once an op is claimed to a layout its fallback cannot decode, internal executor decline points must throw ggml_sycl_fallback_error instead of returning false.
- [Flag presence-test](flag-presence-test.md) — Reading an env var as getenv != nullptr, so =0 enables the behavior and only unset disables it (GGML_SYCL_UNIFIED_FORCE_LEGACY), with static latching per process.
- [Free-VRAM confound](free-vram-confound.md) — A B70 run reporting ~13.8 GB instead of ~32.6 GB is confounded (e.g., by ComfyUI) and discarded; holders verified via a drm-pdev fdinfo sweep.
- [Host bounce](host-bounce.md) — Transferring data device→host→device as a fallback when direct P2P is unavailable; validated via ONEAPI_DEVICE_SELECTOR=level_zero:0,1.
- [iGPU VRAM budget must not count host RAM](igpu-vram-budget-must-not-count-host-ram.md) — The Arrow Lake-S iGPU reports ~231.7 GB global_mem_size, which is host RAM, not VRAM; the backend's VRAM budget calc (min(total*pct, free_at_init) at a 100% default) is correct for discrete cards but claims the whole host for an integrated GPU. Until fixed, pin ONEAPI_DEVICE_SELECTOR=level_zero:0,1 (llama.cpp-403s).
- [Interleaved A/B design](interleaved-ab-design.md) — Alternating treatment and control arms so session drift loads both equally; blocked designs can invert the sign of a measured effect (−3.6% vs +2.3%).
- [Invalidated vs superseded](invalidated-vs-superseded.md) — Baseline rows measured under a hidden tenant or wrong default arm are invalidated (not gateable) rather than superseded by a newer number.
- [Kernel confirmation from output, not setup](kernel-confirmation-from-output-not-setup.md) — Because the fast-path can bypass setup preconditions, the actually-running kernel must be verified from GGML_SYCL_MUL_MAT_ROUTE_TRACE=1 or an oracle-fit ratio — a passing precondition is not evidence about which kernel ran.
- [Known-stale baseline](known-stale-baseline.md) — A correctly measured number that must no longer gate anything because the measurement conditions (hidden tenant) invalidated it.
- [Layout follows residency](layout-follows-residency.md) — Wherever a weight lives, it is materialized in the optimal layout for the processor that executes on it (per device), and dispatch routes must consume the materialized layout, never the reverse.
- [Lazy re-resolution](lazy-re-resolution.md) — A global generation counter bumped whenever a pointer could have moved makes resolve() a ~3 ns compare-and-return fast path, with resolve_slow() re-querying the cache on a miss so weights can migrate VRAM↔host transparently.
- [Leases (in_use_count)](leases-inusecount.md) — A live WEIGHT handle increments the cache entry's in_use_count; in_use_count == 0 is necessary but not sufficient for eviction — ownership-aware reclaim (weight_entry_reclaimable()) also preserves live-model-owned and MID_LOAD_REPLAN entries.
- [Live card derivation](live-card-derivation.md) — Resolving the DRM card from the PCI device symlink (0000:03:00.0 B70 / 0000:07:00.0 B50) instead of a static cardN index that moves across boots.
- [Masking bug](masking-bug.md) — A hidden co-resident tenant that makes a defect or a slow arm invisible, e.g., the hung llama-cli tenants in llama.cpp-o3h1 or the OpenVINO embedder behind rows A–D.
- [Measurement masking (co-resident tenants)](measurement-masking-co-resident-tenants.md) — A secretly co-resident process (codescout's embedder on B50) inflates baseline measurements, producing invalid baselines that must be filed separately (llama.cpp-9klr) and that make stale baseline rows unusable for gating.
- [Misleading error attribution](misleading-error-attribution.md) — A P2P refusal surfacing as UR/ZE_RESULT_ERROR_OUT_OF_DEVICE_MEMORY (error 39), which can misdirect debugging toward a nonexistent VRAM-budget bug.
- [MMVQ with q8_1 activations](mmvq-with-q81-activations.md) — Production quantized kernel that quantizes activations to 8-bit per 32-element blocks (scale amax/127, per-block fp16 sum), matching the upstream CUDA convention.
- [MMVQ/MMQ/DMMV/ESIMD kernel families](mmvqmmqdmmvesimd-kernel-families.md) — SYCL quantized GEMM kernels dispatched by batch size and force flags; MMVQ is the production batch=1 TG kernel, coalesced DMMV a fallback/debug path.
- [Multi-context device contention](multi-context-device-contention.md) — Winner-holds-forever graph-invocation behavior plus exactly-once DEVICE_BUSY refusal for other contexts; open question under llama.cpp-u7vj (P2), with same-device concurrent inference unsupported per contract §5.
- [Multi-GPU device collapse](multi-gpu-device-collapse.md) — On current Level Zero multi-GPU runtimes the scheduler-visible device set collapses to one device, so all contexts in a process share device 0's registry slot regardless of how many physical GPUs are installed.
- [Multi-GPU MoE (GGML_SYCL_MOE_MULTI_GPU)](multi-gpu-moe-ggmlsyclmoemultigpu.md) — Opt-in multi-device path that moves expert data between cards; host-bounces here because the cards cannot DMA to each other.
- [Never shrink context — place KV instead](never-shrink-context-place-kv-instead.md) — Owner ruling that default n_ctx must stay at the model's max; when KV does not fit VRAM the fix is placement (tiered KV to pinned host), never auto-shrinking n_ctx and never refusing context init. Explicit -c is the only way to get a smaller context.
- [No host waits — event-chain everything](no-host-waits-event-chain-everything.md) — Owner ruling that SYCL dispatch paths must express ordering as event dependencies (depends_on, oneDNN sycl_interop::execute deps), never a host wait/drain per op; waits are confined to teardown, error paths, and debug/init.
- [No weight streaming](no-weight-streaming.md) — Copying host-resident weights into device scratch per dispatch is forbidden (a PCIe copy plus scratch pressure); the answer is CPU expert dispatch overlapped via sycl::depends_on.
- [No zero-copy host reads](no-zero-copy-host-reads.md) — Feeding a host-pinned pointer to a GPU kernel is forbidden — measured slower (11.3 GB/s vs CPU AOS 18–30 GB/s) and a break of the tier abstraction.
- [Non-owning storage-handle route](non-owning-storage-handle-route.md) — Per-expert slices of the buffer's managed_handle that are owning ref-counted leases but not cache entries — published transactionally and consulted by the expert resolver before any cache key is formed.
- [One layout per weight](one-layout-per-weight.md) — The MXFP4 MoE layout chokepoint is a single per-weight planning-time decision with no PP/decode caller identity — no duplicate layouts per weight and no dispatch-time layout shifts.
- [Opt-out (default ON) variable polarity](opt-out-default-on-variable-polarity.md) — Performance-critical GGML_SYCL_* flags default ON and are disabled by opt-out, in contrast to experimental opt-in flags that default OFF.
- [Opt-out performance defaults](opt-out-performance-defaults.md) — The fork's performance-critical SYCL features default ON and are disabled by setting their GGML_SYCL_* variable, so disabling a 'fix' is always an opt-out, not an opt-in.
- [Oracle fit ratio](oracle-fit-ratio.md) — Judging kernel accuracy by the ratio of fit between two oracles (dfloat vs q8_1-MMVQ) rather than by an absolute tolerance.
- [Owner-first allocation](owner-first-allocation.md) — unified_allocate_owner allocates the intrusive alloc_owner_control before the physical allocation, so an allocation can never exist without an owner.
- [PCI/PCIe topology restriction](pcipcie-topology-restriction.md) — A limitation imposed by which root ports/switches a device hangs off, independent of card identity — why the B580→B70 swap in the same slot changed nothing.
- [Peer-to-peer (P2P) DMA](peer-to-peer-p2p-dma.md) — Direct device-to-device memory transfer over PCIe; absent here because the two cards do not share an upstream or whitelisted host bridge.
- [Per-allocation hardware caps](per-allocation-hardware-caps.md) — Clean enforcement of per-allocation size limits by the patched runtime; reverting to stock without the old allocation check can reintroduce silent oversized-allocation hangs.
- [PL2 throttling](pl2-throttling.md) — throttle/status or act_freq nonzero under tile0/gt0/freq0; alone decayed identical-binary readings 2–5× with a clean kernel log.
- [Placement decided once](placement-decided-once.md) — Placement is chosen for fit and execution optimality in a single planning pass and is never re-litigated by the dispatcher at op time; symmetric failure modes (zero-copy reads, weight streaming) are structurally forbidden.
- [Placement decides the executor](placement-decides-the-executor.md) — The planning pass decides where data lives; inference then executes each op where its data already is — VRAM operand on that GPU, host-pinned operand on the CPU.
- [Placement / lifetime / transient-view triad](placement-lifetime-transient-view-triad.md) — The core invariant: the cache owns placement, the mem_handle owns lifetime, and a raw pointer is only a transient view resolved for one immediate use and never stored.
- [Placement plan](placement-plan.md) — The model-load-time plan (compute_placement_plan → placement_plan) that is the sole authority for where weights, MoE experts, KV layers, and scratch live, assigning each a device and VRAM zone.
- [PP512 / TG128](pp512-tg128.md) — Prompt-processing (512-token) and token-generation (128-new-token) throughput metrics in tok/s.
- [Presence-tested env var](presence-tested-env-var.md) — GGML_SYCL_UNIFIED_FORCE_LEGACY is checked via getenv != nullptr, so =0 enables the bypass and the static latches per process.
- [q8_1 activation quantization](q81-activation-quantization.md) — MMVQ's activation format: 8 bits per 32-element block, scale amax/127, per-block sum, both stored as fp16, matching the upstream CUDA convention.
- [Refusible release](refusible-release.md) — Dropping the last reference calls into the device's allocation_release_coordinator, which may return RETRY_SCHEDULED; the retry is queued via a retry_next_ pointer that allocates nothing, so it works under memory pressure.
- [Routing-dependent flag effect](routing-dependent-flag-effect.md) — A dispatch flag whose cost depends on the model's default routing — a no-op on GPT-OSS but ~⅔ PP loss on Mistral.
- [Scratch ring admission](scratch-ring-admission.md) — The MoE oneDNN scratch ring is sized for all n_expert experts and admission is fail-closed (since f2bdfbffe), so plan-time sizing mistakes (e.g. stale WOQ arm choice) make admission refuse every dispatch.
- [Session drift](session-drift.md) — Within-session throughput drift (a B50 block climbed 7% across five identical runs) that makes sequential blocks inseparable from flag effects.
- [Shmem ceiling](shmem-ceiling.md) — Shmem in /proc/meminfo above 10 GB, the TTM-shmem OOM signature this repo has hit repeatedly.
- [Sign flip under blocked design](sign-flip-under-blocked-design.md) — Same-flag measurements yielding −3.6% (sequential) vs +2.3% (interleaved), showing blocked output is not a measurement of the flag.
- [Single allocation entry point](single-allocation-entry-point.md) — All runtime/scratch/staging/KV/compute allocation goes through unified_allocate, which routes by alloc_intent to a tier and VRAM zone; a raw sycl::malloc may occur only inside the cache implementation.
- [Single-allocator invariant](single-allocator-invariant.md) — All backend allocation flows through one allocator (the unified cache) and is owned by one lifetime token (mem_handle); raw allocation calls, raw pointer keying, and stored raw pointers are forbidden.
- [stable_identity_hash](stableidentityhash.md) — The stable handle identity used to key pointer tables and dispatch caches, in place of a transient device pointer.
- [Staging scope boundary](staging-scope-boundary.md) — Staging that converts the format of device-resident data (e.g., on-device MXFP4 dequant to f16 scratch) is not a placement violation — the rule governs residency, not layout conversion — but such conversion scratch belongs to planned zones.
- [Stale GPU tenant](stale-gpu-tenant.md) — A live llama-cli/llama-bench/llama-completion process that depresses co-taken readings and can mask a real hardware defect.
- [SYCL graph replay](sycl-graph-replay.md) — Command-graph record/replay submission path; a replay-active graph currently never reaches a terminal state, so its invocation is held indefinitely (release_invocation no-ops), blocking other contexts with a one-shot DEVICE_BUSY.
- [Tensor identity (ggml_sycl_cache_id)](tensor-identity-ggmlsyclcacheid.md) — The stable identity key for WEIGHT handles, distinct from the transient pointer; a tensor that never went through a minting occasion has no owner and cannot be admitted at all.
- [TG fast-path](tg-fast-path.md) — The ggml_sycl_mul_mat() shortcut for batch=1 quantized non-AoS MUL_MAT — it dispatches MMVQ and returns before any FORCE_DMMV or LAYOUT_OVERRIDE read, so MMVQ is the production TG kernel.
- [TG vs PP](tg-vs-pp.md) — Token generation (decode, batch=1) and prompt processing (batch>1) are the two workload axes the flags tune separately; many changes bank a PP win at a TG cost or vice versa (e.g. Q8_DENSE_AOS).
- [Tiered memory hierarchy](tiered-memory-hierarchy.md) — Device VRAM → pinned host → mmap hierarchy that the cache must be free to migrate allocations between at any time without dangling pointers.
- [Typed allocation errors](typed-allocation-errors.md) — allocation_result::error distinguishes INVALID_REQUEST, CONTROL_ALLOCATION_FAILED, PHYSICAL_ALLOCATION_FAILED, METADATA_PUBLICATION_FAILED, and RELEASE_RETAINED.
- [USM compression (upstream PR 930)](usm-compression-upstream-pr-930.md) — Upstream USM compression fix included in the patched compute-runtime build.
- [USM (Unified Shared Memory)](usm-unified-shared-memory.md) — Unified shared-memory allocation model; a direct D2D USM copy between the two cards fails in both directions despite ample free VRAM.
- [VRAM budget](vram-budget.md) — The enforced device-memory cap min(total*pct, free_at_init) that gates allocation and eviction behavior.
- [VRAM zone](vram-zone.md) — Budgeted fixed regions of the VRAM arena (vram_zone_id: KV, WEIGHT, ONEDNN, RUNTIME, SCRATCH) allocated via arena/zone TLSF sub-allocation.
- [WEIGHT handle leases](weight-handle-leases.md) — Weights are handed out as WEIGHT-kind handles keyed by tensor identity that hold a lease (in_use_count) on the cache entry; lazy generation-counter resolution permits transparent VRAM↔host migration, and eviction may only remove entries with in_use_count == 0.
- [Weight memory layouts (SOA / AOS / COALESCED / XMX_TILED)](weight-memory-layouts-soa-aos-coalesced-xmxtiled.md) — Per-weight data layouts for quantized weights, chosen by the layout policy at planning time under the one-layout-per-weight rule; overridable per-weight via GGML_SYCL_LAYOUT_OVERRIDE.
- [Winner-holds-forever DEVICE_BUSY](winner-holds-forever-devicebusy.md) — Multi-context failure mode where the first context to begin a tracked graph on a device holds its invocation indefinitely and every other context's claim is refused exactly once with no path to later success; under open P2 adjudication (llama.cpp-u7vj).
- [WOQ GEMM (weight-only-quantized)](woq-gemm-weight-only-quantized.md) — Batched oneDNN matmul consuming 4-bit MXFP4 weights plus e8m0 scales directly (repacked into ~4x-smaller scratch), avoiding f16 dequant; runs woq_gemm_batch_mxfp4.
- [XMX_TILED grouped-DPAS route](xmxtiled-grouped-dpas-route.md) — Intel XMX matrix-extend grouped-DPAS kernel route for MXFP4 MoE gate/up/down projections, selected by planner/admission gates at layout time; productized for PP and enabled for the down projection.
