# sycl-env-vars.md

## Summary

This document is a curated (explicitly non-exhaustive) catalog of `GGML_SYCL_*` tuning and debugging environment variables for the SYCL backend of a llama.cpp fork. It provides a grep recipe for inventoring variable-name string literals in `ggml/src/ggml-sycl`, warns that the match set includes names retained only for compatibility, diagnostics, comments, or removal notices (so a live read must be confirmed before treating any name as an active setting), and notes that `CLAUDE.md` keeps only the handful of load-bearing performance opt-outs. The catalog is organized into three groups: performance-critical variables that default ON and are opt-out (`GGML_SYCL_UNIFIED_SOA`, `GGML_SYCL_TG_FAST`, `GGML_SYCL_DISABLE_GRAPH`, `GGML_SYCL_ONEDNN_PP`, `GGML_SYCL_UNIFIED_FORCE_LEGACY`, `GGML_SYCL_XMX_TILED_PP`, `GGML_SYCL_MOE_DOWN_XMX_TILED`, `GGML_SYCL_Q8_DENSE_AOS`, `GGML_SYCL_Q8_ONEDNN_COALESCED`, `GGML_SYCL_MOE_PP_ONEDNN_F16_BATCHED`, `GGML_SYCL_MOE_PP_WOQ`, `GGML_SYCL_MOE_PP_WOQ_3D`); experimental opt-in variables off by default (`GGML_SYCL_PP_PIPELINE`, `GGML_SYCL_XMX_MOE_SORTED`); and kernel dispatch tuning knobs (FORCE_MMVQ/ESIMD/MMQ/DMMV, ESIMD/oneDNN min-batch thresholds, `GGML_SYCL_ONEDNN_MUL`, `GGML_SYCL_FA_ONEDNN_MATERIALIZE`, `GGML_SYCL_BATCH_EXPERTS`, `GGML_SYCL_ESIMD_DEQUANT`, `GGML_SYCL_LAYOUT_OVERRIDE`, `GGML_SYCL_USE_XMX_GEMM` + `GGML_SYCL_XMX_THRESHOLD`, `GGML_SYCL_MXFP4_GROUPED_DPAS_ROW_LIST_TILES`). Each entry carries dated measurement histories tied to llama.cpp-* tickets (e.g., the 2026-08-25 owner ruling c-mnd7 flipping `GGML_SYCL_MOE_PP_ONEDNN_F16_BATCHED` to default ON on both B50 and B70 after clean-host certification, and the 2026-08-20 sk67 change that made `GGML_SYCL_MOE_DOWN_XMX_TILED` actually functional).

Two structural discussions dominate the document. First, `GGML_SYCL_DISABLE_GRAPH` controls graph replay (not graph-compute concurrency): with replay ON, the first context to begin a tracked graph on a device holds its invocation indefinitely — a replay-active graph never reaches a terminal state, so `release_invocation` silently no-ops — and every other context's claim on that device is refused `DEVICE_BUSY` exactly once with no later success path. The flag is therefore currently load-bearing for multi-context workloads "rather than a setting to recommend"; `test-thread-safety` passes at 6.95 s with replay off and fails at 3.4 s with replay on, but its ctest registration sets the flag (llama.cpp-b16a/cnre), so its green result is not evidence that multi-context works on the default configuration. The winner-holds-forever behavior is being adjudicated as intended exclusivity vs. gap under llama.cpp-u7vj (open, P2), and on current Level Zero multi-GPU runtimes the scheduler-visible device set collapses to one device, so all contexts share device 0's registry slot regardless of physical GPU count. Second, the TG fast path in `ggml_sycl_mul_mat()` short-circuits batch=1 quantized MUL_MAT on GPU-accessible non-AoS weights, dispatching MMVQ with q8_1 activations and returning upstream of both `GGML_SYCL_FORCE_DMMV` reads and of the `GGML_SYCL_LAYOUT_OVERRIDE` kernel choice; MMVQ is thus the production TG kernel, `GGML_SYCL_FORCE_DMMV=1` alone changes nothing at batch=1, and a passing layout precondition is not evidence about which kernel ran. The document closes with the lesson from llama.cpp-szv8, which spent three RCA rounds on a test where every structural precondition passed but the kernel under test never executed: confirm the kernel from output (e.g., `GGML_SYCL_MUL_MAT_ROUTE_TRACE=1` or an oracle-fit ratio), never from setup.

## Key Takeaways

- The catalog is curated, not exhaustive: string-literal grepping surfaces compatibility/diagnostic names too, so confirm a live read before treating a name as an active setting.
- Performance-critical variables default ON and are opt-out; CLAUDE.md tracks only the load-bearing performance opt-outs.
- The TG fast path claims batch=1 quantized MUL_MAT before GGML_SYCL_FORCE_DMMV or GGML_SYCL_LAYOUT_OVERRIDE are read — MMVQ is the production TG kernel, FORCE_DMMV alone is inert at batch=1, and the kernel must be confirmed from output (MUL_MAT_ROUTE_TRACE / oracle-fit ratio), not from setup.
- GGML_SYCL_DISABLE_GRAPH=1 is currently load-bearing for multi-context workloads but is an open question, not a recommendation: with replay ON the first context holds its graph invocation forever and other contexts get DEVICE_BUSY exactly once (test-thread-safety passes only because its ctest registration sets the flag; adjudication under llama.cpp-u7vj, P2).
- On current Level Zero multi-GPU runtimes the scheduler-visible device set collapses to one device, so all in-process contexts share device 0's registry slot; same-device concurrent inference remains unsupported per the canonical contract §5.
- GGML_SYCL_MOE_PP_ONEDNN_F16_BATCHED flipped to default ON on both B50 and B70 (llama.cpp-iikr, 2026-08-25, owner ruling c-mnd7) after clean-host certification; its superseded default-arm baselines were invalid (codescout's embedder secretly resident), and the true default-route collapse (~130 B50 / ~515 B70 pp512) is filed as llama.cpp-9klr (P2), NOT fixed by the flip.
- The WOQ 3-D scale-mask arm (GGML_SYCL_MOE_PP_WOQ_3D) is known-broken: oneDNN accepts it but reproducibly produces wrong numerics on the down role (B70); it stays opt-in only so a separate follow-up can iterate — do not re-enable in production.
- GGML_SYCL_MOE_DOWN_XMX_TILED semantics changed 2026-08-20 (llama.cpp-sk67) from OFF+no-op to ON+functional: the grouped-DPAS down route now reaches all 24 MoE layers on B50 instead of the SOA fallback (which was 92% of B50 MoE device time).
- Q8 dense layout tradeoff: GGML_SYCL_Q8_DENSE_AOS gains +38% B70 pp512 (847→1160) but loses −34% B50 tg128 (32.1→21.3), so it defaults OFF and is superseded by GGML_SYCL_Q8_ONEDNN_COALESCED, which gets the oneDNN gemm arm without moving TG off the coalesced kernel.
- Fail-closed contract in the batched PP MoE oneDNN executor: once an op is claimed as XMX_TILED, every internal decline point throws ggml_sycl_fallback_error instead of returning false, because the remaining per-expert staging fallback cannot decode XMX_TILED weights (llama.cpp-71hx).
- GGML_SYCL_MOE_PP_WOQ=0 (f16 dequant opt-out) is SOA-only: the f16 dequant kernel has no tiled-aware counterpart, so with =0 an XMX_TILED gate/up op is never claimed and falls through to its pre-C3 route unchanged.
- GGML_SYCL_FA_ONEDNN_MATERIALIZE polarity reversed to default OFF on 2026-08-10 (llama.cpp-olpg): DIRECT is numerically correct at D=16/D=128 and =1 is retained only as the A/B axis; text describing the original ON default predates the ruling.
- Experimental XMX GEMM (GGML_SYCL_USE_XMX_GEMM, threshold default 64) is measured 5–11x slower for quantized models and requires both GGML_SYCL_XMX_GEMM and GGML_SYCL_MMQ_XMX build flags; the SOA direct-XMX/DPAS gate/up decode kernel is a measured 2x regression (25.8 vs 12.26 ms/token) — a documented dead end.
- The 1.9x-slower figure behind the GGML_SYCL_ESIMD_DEQUANT default was measured on an Arc B580 + oneAPI 2025.3 no longer in the machine (replaced by B70) — historical justification, not a current measurement (same stale claim copied in CLAUDE.md).

## Contradictions

⚠️ **Contradiction**: GGML_SYCL_Q8_DENSE_AOS wins and loses simultaneously: +38% B70 pp512 (847→1160) but −34% B50 tg128 (32.1→21.3), so it defaults OFF and is superseded by GGML_SYCL_Q8_ONEDNN_COALESCED, which gets the oneDNN arm without the TG loss.
⚠️ **Contradiction**: The previously recorded default-arm baselines (~894/~1415 pp512) are invalid: they were measured with codescout's embedder secretly resident on the B50 (the same masking-bug class llama.cpp-o3h1 fixed). On a genuinely clean host the default (non-batched) arm collapses to ~130 (B50) / ~515 (B70) pp512 — filed as llama.cpp-9klr (P2), NOT fixed by the iikr flip, and docs/backend/sycl-perf-baselines.md's old default-route rows are known-stale and must not be gated against.
⚠️ **Contradiction**: test-thread-safety's green result is not evidence that multi-context works on the default configuration: it passes only because the ctest registration itself sets GGML_SYCL_DISABLE_GRAPH=1 (llama.cpp-b16a/cnre disposition).
⚠️ **Contradiction**: GGML_SYCL_FA_ONEDNN_MATERIALIZE's documented default contradicts the current state: it was introduced by llama.cpp-l7rt defaulting ON as a pure measurement axis, but the polarity reversed to default OFF on 2026-08-10 (llama.cpp-olpg owner ruling) — any text describing the ON default predates the ruling.
⚠️ **Contradiction**: The 1.9x-slower ESIMD small-block dequant figure justifying the GGML_SYCL_ESIMD_DEQUANT default is stale: measured on an Arc B580 + oneAPI 2025.3 that is no longer in the machine (replaced by B70), so it is historical justification, not a current measurement; the same claim is duplicated in CLAUDE.md.
⚠️ **Contradiction**: The 3-D WOQ scale-mask primitive is accepted by oneDNN (no refusal in the log) yet reproducibly produces wrong numerics on the down role (blk.0 gpu=-5.21 vs cpu=-484.47, NaN cascade by blk.1) while the 2-D loop on the same hardware is clean — accepted ≠ correct.
